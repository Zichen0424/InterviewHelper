# Agent 工程实践：工具调用与执行边界

公司：星野数智（示例）
岗位：AI Agent 开发工程师
日期：2026-09-21
标签：Agent、LangGraph、Function Calling、工具调用、工作流、评测
摘要：以自动生成经营日报的智能体为例，讨论工具选择、状态管理、失败恢复、权限控制以及如何评测端到端任务。

> 本文是用于产品演示的虚构面经。

我介绍了一个读取数据库报表、生成图表并撰写摘要的 Agent。实现时用 LangGraph 表达工作流状态，把查询、绘图和报告生成作为独立工具。面试官没有要求堆叠多个 Agent，而是追问每次工具调用的输入输出是否可观察。

- Function Calling 返回了错误参数时，应如何校验并重试？
- Agent 在连续调用工具时，如何保存状态并避免重复执行有副作用的操作？
- 用户提示词试图诱导 Agent 读取无权限数据时，边界应放在哪里？
- 固定工作流和自主规划 Agent 分别适合什么任务？
- 如何设计 Agent 的任务完成率、工具错误率和人工接管率评测？

我说明了工具权限由服务端账号决定，不能只依赖模型提示词。对于失败的步骤，工作流记录执行结果，允许从安全的检查点恢复。
