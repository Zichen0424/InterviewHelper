# MCP 接入：把内部工具交给 AI 助手

公司：云杉科技（示例）
岗位：AI 平台开发工程师
日期：2026-09-20
标签：MCP、Model Context Protocol、工具协议、资源、权限控制
摘要：围绕内部文档与工单系统的 MCP 接入，讨论工具和资源的暴露方式、参数校验、认证、审计与客户端兼容。

> 本文是用于产品演示的虚构面经。

团队希望让 AI 助手通过 MCP 读取知识库、查询工单并创建草稿。我负责封装工具接口，区分只读查询与需要确认的写操作。面试官重点考察服务端如何限制权限，以及接口变化后如何兼容已有客户端。

- MCP 中工具与资源分别适合暴露什么能力？
- 怎样为 MCP 工具定义输入参数，并处理模型传来的非法值？
- 多个用户共用 MCP 服务时，如何隔离凭证和访问范围？
- 工具执行超时或返回部分结果时，客户端应如何感知？
- 如何记录一次 AI 工具调用的审计信息，同时避免日志泄露敏感数据？

我强调服务端必须根据实际用户身份检查权限。模型输出只代表一次请求，不能直接作为授权依据。上线前会准备不同客户端的协议测试和失败场景。
