# 大模型部署：vLLM 推理服务的吞吐与延迟

公司：沐光计算（示例）
岗位：大模型应用开发工程师
日期：2026-09-19
标签：vLLM、模型部署、推理服务、GPU、量化、LoRA
摘要：以企业内部模型服务为背景，讨论 vLLM 部署、并发请求下的延迟和吞吐、GPU 显存预算，以及量化和 LoRA 适配器的取舍。

> 本文是用于产品演示的虚构面经。

我介绍了把模型部署成推理 API 的经历。试运行时使用 vLLM，观察不同输入长度和并发量下的首 token 延迟、整体吞吐与 GPU 显存占用。面试官要求我区分离线批处理与在线交互的指标目标。

- vLLM 的连续批处理为什么能改善吞吐，可能带来哪些延迟变化？
- GPU 显存不足时，怎样估算模型权重和 KV Cache 的开销？
- 量化可能影响哪些质量指标，如何决定是否上线？
- 多个 LoRA 适配器共用一个推理服务时，如何管理版本和路由？
- 推理服务突然变慢，应该先观察队列、输入长度还是硬件利用率？

我会用固定测试集对比部署前后的回答质量，再对线上请求统计 P50、P95 延迟和失败率。容量规划要同时考虑平均流量与突发流量。
