# 从缓存到一致性：一场后端技术面试

公司：星河科技（示例）
岗位：Java 后端工程师
日期：2026-09-18
标签：Redis、MySQL、分布式、Java
摘要：面试围绕高并发订单系统展开，从 Redis 缓存问题深入到数据库事务与消息幂等，重点关注方案的取舍和真实排障经历。

> 本文是用于产品演示的虚构面经。

一面大约 60 分钟，先介绍了订单系统的项目背景。面试官沿着缓存和数据库的数据一致性持续追问，比较看重为什么这样设计，而不是单纯背概念。

## 缓存与数据库
- Redis 缓存穿透、击穿和雪崩分别是什么？如何避免热点 key 失效拖垮数据库？
- 先更新数据库还是先删除缓存？并发请求下如何保证最终一致性？
- MySQL 联合索引遵循什么规则？怎样分析一条慢查询？
- MVCC 如何实现事务隔离？可重复读能解决所有幻读问题吗？

## 项目深入
- 订单消息重复消费时如何保证幂等？
- 如果消息发送失败，但数据库事务已提交，系统应该怎样补偿？

最后聊了线上故障处理。我提到了通过监控定位热点请求，再用限流和缓存预热降低数据库压力的经历。面试官希望看到指标变化以及方案代价。
